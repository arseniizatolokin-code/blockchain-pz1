# Власний блокчейн з нуля (ПЗ 1)

Навчальна криптовалюта на Python: гаманці з підписами Ed25519, мемпул, дерево Меркла, Proof of Work з автоматичною
складністю, мережа з кількох вузлів (HTTP), вибір найважчого ланцюга при форку, консольний клієнт.
Готові бібліотеки використано лише для криптографічних примітивів (SHA-256 з `hashlib`, Ed25519 з `cryptography`)
та для HTTP (Flask, requests). Дерево Меркла, блоки, ланцюг, мемпул, майнінг, консенсус написані самостійно.

Додаткові завдання: легкий клієнт із доказом Меркла (`light_client.py`) та атака 51 % (`attack51.py`).

## Встановлення

```
pip install -r requirements.txt
```

Потрібен Python 3.10+.

## Запуск мережі з трьох вузлів

```
python run_network.py
```

Вузли стартують на `http://127.0.0.1:5001`, `5002`, `5003`, знають один одного і зберігають ланцюг у `data/node_<порт>.json`.
Один вузол вручну: `python node.py --port 5001 --peers http://127.0.0.1:5002`.

## Консольний клієнт

```
python cli.py wallet new alice
python cli.py wallet new bob
python cli.py --node http://127.0.0.1:5001 mine --wallet alice
python cli.py --node http://127.0.0.1:5001 send --wallet alice --to bob --amount 20 --fee 2
python cli.py --node http://127.0.0.1:5002 mempool
python cli.py --node http://127.0.0.1:5003 mine --wallet bob
python cli.py --node http://127.0.0.1:5001 chain
python cli.py --node http://127.0.0.1:5001 balance alice
python cli.py --node http://127.0.0.1:5001 validate
python cli.py --node http://127.0.0.1:5001 peer http://127.0.0.1:5004
python cli.py --node http://127.0.0.1:5001 sync
python cli.py --node http://127.0.0.1:5003 network off      # імітація розриву мережі (on — повернути)
```

Параметр `--to` приймає адресу або ім'я локального гаманця. Гаманці лежать у `wallets/*.json` (приватні ключі, у git не потрапляють).

## Основні рішення

- **Модель рахунків** (як в Ethereum), а не UTXO: баланс і nonce кожної адреси зберігаються в стані, який повністю відтворюється з блоків.
- **Адреса** = перші 20 байтів SHA-256 від публічного ключа. У транзакції є поле `pubkey`, бо вузлу потрібен ключ, щоб перевірити підпис.
- **Підпис** покриває всі поля транзакції, крім самого підпису. **tx_id** = SHA-256 від транзакції разом із підписом.
- **Серіалізація** детермінована: канонічний JSON (відсортовані ключі, без пробілів) для транзакцій та рядок `index|timestamp|prev_hash|merkle_root|difficulty|nonce` для заголовка.
- **Складність у бітах**: хеш має починатися з `difficulty` нульових бітів. 4 біти = 1 hex-нуль, тому +1 hex-нуль робить майнінг у 16 разів довшим.
  Початкова складність 12 біт, коригування кожні K=10 блоків (до ±2 біти за раз), ціль 10 с на блок. Значення задаються в `chain/config.py` або змінними `BC_DIFFICULTY`, `BC_K`, `BC_TARGET`.
- **Винагорода**: 50 монет + усі комісії блоку. Це перша транзакція блоку (coinbase), її nonce дорівнює висоті блоку.
- **Мемпул** перевіряє: підпис, дублікат (у черзі й у ланцюгу), nonce (суворо наступний), баланс з урахуванням уже очікуваних витрат.
- **Консенсус**: вузол бере ланцюг із найбільшою сумарною роботою (сума 2^складність), а не просто найдовший. Кожен чужий ланцюг повністю перевіряється з генезису.
  Транзакції з відкинутих блоків повертаються в мемпул, якщо ще дійсні.
- **Сусіди** додаються командою `peer`; блоки й транзакції розсилаються сусідам у фоні. Блок, який не продовжує ланцюг, запускає синхронізацію.

## Обмеження (чесно)

- Дерево Меркла дублює останній листок при непарній кількості, тому відомий випадок CVE-2012-2459 (два різні набори листків із однаковим коренем) теоретично можливий; у нас це не дає атаки, бо дублікат tx_id відхиляється правилами блоку.
- Ні шифрування каналу, ні автентифікації вузлів немає; заголовок `X-Peer` лише позначає запити між вузлами.
- Мережа працює на одній машині, ідентифікація сусідів за URL, без пошуку вузлів.
- Майнінг на Python повільний (~1,8 млн хешів/с), тому складність у демо мала.
- Розв'язок форку: при однаковій роботі вузол лишає перший отриманий ланцюг.
- Мітки часу довіряються в межах «не раніше попереднього блоку і не далі ніж на 2 години в майбутнє».
- Немає UTXO-приватності, скриптів, лімітів розміру блоку в байтах (лише в кількості транзакцій).
